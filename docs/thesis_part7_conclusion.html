CHAPTER 7: CONCLUSION AND FUTURE WORK

7.1 Summary of Achievements

This project has successfully designed, implemented, and validated NTTH (No Time To Hack), an agent-inspired autonomous network defense architecture that bridges the critical gap between threat detection and containment. The system represents a significant advancement over traditional IDS platforms by integrating detection, scoring, decision-making, enforcement, and intelligence gathering into a single closed-loop pipeline operating on commodity hardware.

The key achievements of this project are:

  1. Complete closed-loop autonomous pipeline: A four-stage agent-inspired pipeline (Threat Assessment → Decision Making → Enforcement → Reporting) coordinated through an asynchronous event bus processes packets from capture to enforcement in approximately 127 milliseconds — eliminating the 15–30 minute manual response gap identified in the literature.
  2. Hybrid risk scoring model: A weighted combination of signature-based IDS rules (7 sliding-window detectors: port scan, host sweep, stealth scan, SYN flood, ICMP flood, ARP sweep, brute force) and Isolation Forest unsupervised anomaly detection provides both deterministic known-attack detection and probabilistic novel-attack identification without requiring labeled training data.
  3. Real kernel-level enforcement: Linux nftables and iptables firewall rules are applied automatically at the kernel level, providing block, rate-limit, and honeypot redirect capabilities. The system processes packets in the kernel's netfilter framework, ensuring enforcement cannot be bypassed by user-space processes.
  4. Flow-aware dynamic honeypot deployment: Unlike static honeypots that sit idle until manually targeted, NTTH creates targeted DNAT redirection rules for specific attacker-victim-port flows in real-time. Each honeypot session is linked to the original threat assessment through a redirect context registry, enabling full forensic correlation.
  5. Intelligent threat escalation: The system implements graduated response — observing attackers through honeypot interactions (gathering credentials, commands, and malware URLs) before escalating to full IP blocking. Per-IP scan counters ensure attackers are given exactly enough rope to expose their methods before containment.
  6. Full-featured real-time dashboard: A Flutter Web + Android application with 9 screens provides real-time visualization of threats, devices, firewall rules, honeypot sessions, and network topology via persistent WebSocket connections with sub-second event delivery.
  7. Commodity hardware deployment: The entire system — backend server, ML engine, packet capture, honeypot containers, and firewall enforcement — runs on a single Ubuntu laptop ($500) with a $10 USB WiFi adapter. This makes enterprise-grade autonomous defense accessible to small organizations and educational institutions that cannot afford dedicated security appliances.
  8. Validated with real attacks: The system has been tested with 7 distinct attack types (port scan, host sweep, stealth scan, SSH brute force, SYN flood, ICMP flood, ARP sweep) from multiple KVM-based attacker VMs, successfully detecting and autonomously containing all attack categories.

7.2 Limitations

While NTTH demonstrates the feasibility of autonomous network defense on commodity hardware, several limitations must be acknowledged:

  • Single-host deployment: The current implementation monitors from a single network vantage point (the bridge gateway). Multi-hop or distributed network segments require multiple NTTH instances with centralized coordination, which is not yet implemented.
  • 2.4 GHz WiFi monitoring only: The Atheros AR9271 USB adapter operates exclusively on the 2.4 GHz band. Modern networks increasingly use 5 GHz and 6 GHz bands, which would require additional hardware (e.g., Intel AX200 for 5 GHz/6 GHz monitor mode).
  • No encrypted payload inspection: The system analyzes packet headers and metadata (10-dimensional feature vector) but cannot inspect encrypted TLS/SSL payload content. Advanced attacks using encrypted command-and-control channels may evade detection.
  • Per-packet feature model: The 10-dimensional feature vector captures single-packet characteristics. It does not model temporal sequences (e.g., TCP state machine behavior) or flow-level statistics (e.g., bytes per flow, inter-arrival times). Adding temporal features could improve detection of slow, low-and-slow attacks.
  • Static policy thresholds: The Decision Agent uses deterministic risk score thresholds (0.15/0.25/0.40/0.80) and scan count thresholds (6 scans → block). While effective, these thresholds do not adapt to changing network conditions or evolving attack patterns.
  • Limited scalability testing: The system has been validated with 5 devices and 26,000+ packets. Performance under enterprise-scale traffic (10,000+ devices, millions of packets per day) has not been characterized.
  • Conntrack dependency: DNAT-based honeypot redirection relies on Linux conntrack for connection state tracking. Stale conntrack entries from connections established before rule creation may not be redirected, requiring explicit conntrack flushing.

7.3 Future Work

Several promising research directions emerge from this work:

  1. Adaptive Feedback Agent: Implement a fifth pipeline stage that receives administrator feedback on false positives and automatically adjusts risk score thresholds and Isolation Forest contamination parameters. This would transform the system from agent-inspired to fully adaptive, implementing a perception-learning-action cycle. Techniques such as online learning and incremental model retraining could be explored.
  2. Temporal Feature Engineering: Extend the feature vector from per-packet (10 dimensions) to flow-level features (30+ dimensions) including bytes per flow, packet inter-arrival time statistics, TCP state machine progression, and DNS query patterns. This would enable detection of advanced persistent threats (APTs) that operate below per-packet detection thresholds.
  3. Reinforcement Learning Decision Engine: Replace the deterministic threshold-based Decision Agent with a Deep Q-Network (DQN) or Proximal Policy Optimization (PPO) agent that learns optimal response strategies through interaction with the environment. The reward function could incorporate threat containment success, false positive cost, and network disruption penalties.
  4. LLM-Powered Honeypot Responses: Integrate Large Language Model (LLM) powered responses into the Cowrie SSH honeypot to generate context-aware, realistic command outputs that increase attacker engagement duration. Current Cowrie sessions average less than 60 seconds; LLM responses could extend this to several minutes, capturing more intelligence.
  5. Distributed Multi-Sensor Architecture: Extend the system to a hub-and-spoke model where multiple NTTH sensors monitor different network segments and report to a centralized event bus coordinator. This would enable enterprise-scale deployment with correlated threat intelligence across segments.
  6. 5 GHz / 6 GHz Wireless Monitoring: Integrate support for modern WiFi monitoring using Intel AX200/AX210 adapters that support 5 GHz and 6 GHz bands in monitor mode. This would extend wireless threat detection to cover the full spectrum of modern WiFi deployments.
  7. CICIDS2017 Benchmark Validation: Train and evaluate the Isolation Forest model on the 2.8 million record CICIDS2017 benchmark dataset to enable standardized comparison with published IDS research. This would provide reproducible, peer-comparable detection metrics.
  8. Threat Intelligence Sharing: Implement STIX/TAXII integration to share detected threat indicators (attacker IPs, honeypot-captured credentials, malware URLs) with community threat intelligence platforms, contributing to collective defense.
