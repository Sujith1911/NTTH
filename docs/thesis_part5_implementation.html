4.3 Backend Implementation

4.3.1 Application Entry Point (main.py)

The FastAPI application initializes all components on startup through a lifespan context manager. This ensures all subsystems — database, event bus, packet sniffer, honeypots, and scheduled tasks — are started in the correct order and gracefully shut down on termination.

@asynccontextmanager
async def lifespan(app: FastAPI):
    # 1. Initialize database tables
    await init_db()
    
    # 2. Seed admin user
    await create_user(db, settings.admin_username, 
                      hash_password(settings.admin_password))
    
    # 3. Start asynchronous event bus
    await start_event_bus()
    
    # 4. Start background scheduler
    await start_scheduler()
    
    # 5. Start Scapy packet sniffer
    sniffer_task = asyncio.create_task(start_sniffer())
    
    # 6. Start HTTP honeypot (port 8888)
    honeypot_task = asyncio.create_task(start_http_honeypot())
    
    # 7. Start Cowrie JSON log watcher
    cowrie_task = asyncio.create_task(watch_cowrie_log())
    
    # 8. Periodic network scan (every 5 min)
    scan_task = asyncio.create_task(_periodic_scan())
    
    yield  # Application is running
    
    # Shutdown: cancel all tasks
    for task in [sniffer_task, honeypot_task, cowrie_task, scan_task]:
        task.cancel()
    await stop_event_bus()

4.3.2 Packet Sniffer (packet_sniffer.py)

The packet sniffer uses Scapy's AsyncSniffer to capture all IP packets on the bridge interface. It runs in the host's network namespace to access real LAN traffic. Each captured packet is processed through the feature extractor and published to the event bus for threat analysis. The sniffer uses a BPF filter ("ip") to capture only IPv4 traffic, reducing processing overhead from ARP and other Layer-2 frames.

async def start_sniffer():
    from scapy.all import AsyncSniffer
    
    def _packet_callback(pkt):
        features = extract_features(pkt)
        if not features:
            return
        # Update live stats and device registry
        update_live_stats(features)
        registry_update(features)
        # Publish to event bus (thread-safe)
        asyncio.run_coroutine_threadsafe(
            publish("device_seen", features), loop
        )
    
    sniffer = AsyncSniffer(
        prn=_packet_callback,
        store=False,
        filter="ip",
        iface=settings.network_interface
    )
    sniffer.start()

The store=False parameter is critical for memory safety — without it, Scapy would store every captured packet in memory, leading to out-of-memory conditions during sustained traffic. The callback uses asyncio.run_coroutine_threadsafe because Scapy's sniffer runs in a separate thread, while the event bus operates in the asyncio event loop.

4.4 Agent Code Walkthrough

4.4.1 Threat Agent (threat_agent.py)

The Threat Agent is the first processing stage in the pipeline. It subscribes to device_seen events from the packet sniffer and runs the complete IDS + ML scoring pipeline. The agent filters out benign outbound traffic (normal browsing, DNS, HTTPS) from managed devices to prevent false positives from legitimate internet activity.

async def _handle_device_seen(features: dict):
    # Filter: outbound traffic to common service ports is always benign
    if features.get("direction") == "outbound" \
       and is_managed_asset_ip(src_ip) \
       and dst_port in _COMMON_CLIENT_SERVICE_PORTS:
        return
    
    # 1. Rule-based scoring (7 sliding-window detectors)
    rule_result = rule_engine.evaluate(features)
    
    # 2. ML anomaly scoring (Isolation Forest)
    ml_score = anomaly_model.score(features)
    
    # 3. Combined risk calculation
    risk_score = calculate(rule_result["rule_score"], ml_score)
    
    # 4. Determine action with scan-based escalation
    action = determine_action(risk_score, 
                              rule_result.get("threat_type", "normal"),
                              src_ip=src_ip)
    
    if action == "allow":
        return  # Normal traffic, no event
    
    # 5. GeoIP enrichment (non-blocking, best-effort)
    geo_info = lookup(features["src_ip"])
    
    # 6. Publish threat event
    await event_bus.publish("threat_detected", {
        **features, **rule_result,
        "ml_score": ml_score,
        "risk_score": risk_score,
        "action": action,
        **geo_info
    })

# Auto-subscribe at module import

4.4.2 Decision Agent (decision_agent.py)

The Decision Agent implements protocol-aware response selection with intelligent deduplication. It subscribes to threat_detected events and determines the appropriate enforcement action based on threat type, protocol, destination port, and risk score. The agent implements a deduplicate mechanism that allows only one decision per 0.5 seconds for enforcement actions and 2.0 seconds for monitoring actions per unique flow tuple (src_ip, dst_ip, threat_type).

async def _handle_threat_detected(payload: dict):
    src_ip = payload["src_ip"]
    risk_score = payload["risk_score"]
    
    # Skip gateway IP (never block the router)
    if src_ip in {settings.gateway_ip, settings.server_display_ip}:
        return
    
    # Protocol-aware routing: SSH → Cowrie, HTTP → HTTP honeypot
    # Only redirect well-known service ports, not random nmap probes
    _HONEYPOT_PORTS = {21, 22, 23, 80, 443, 3306, 3389, 5432, 5900, 8080}
    if protocol == "tcp" and dst_port in _HONEYPOT_PORTS:
        if dst_port in {21, 22, 23, 3389, 5900}:
            honeypot_port = 30022  # → Cowrie SSH
        else:
            honeypot_port = 8888   # → HTTP honeypot
        action = "honeypot"
    
    await event_bus.publish("enforcement_action", {
        **payload,
        "action": action,
        "incident_context": { ... }
    })

4.4.3 Enforcement Agent (enforcement_agent.py)

The Enforcement Agent translates decision directives into real Linux kernel firewall rules. It operates on the enforcement_action event bus topic and creates nftables (for blocking) or iptables (for DNAT redirection) rules. The agent implements rule deduplication to prevent identical rules from being created multiple times for the same attacker-victim-port flow.

async def _apply_enforcement(payload: dict):
    nft = NFTManager()
    
    if action == "rate_limit":

            src_ip, src_port=dst_port,

            attacker_ip=src_ip,

        # Block forwarded traffic, preserve gateway access
        await nft.add_block(src_ip, reason="...")

4.4.4 Event Bus Core (event_bus.py)

The event bus is the communication backbone connecting all agents. It implements a bounded asyncio queue with publish-subscribe semantics. The single-dispatcher design ensures events are processed sequentially, preventing race conditions in firewall rule creation.

_queue = asyncio.Queue(maxsize=5000)
_subscribers = defaultdict(list)

def subscribe(topic, handler):
    _subscribers[topic].append(handler)

async def publish(topic, payload):
    _queue.put_nowait({"topic": topic, "payload": payload})

async def _dispatch_loop():
    while True:
        event = await _queue.get()
        for handler in _subscribers[event["topic"]]:
            try:
                await handler(event["payload"])
            except Exception as exc:
                log.error("handler_error", error=str(exc))
        _queue.task_done()

4.4.5 Risk Calculator (risk_calculator.py)

The risk calculator combines rule-based and ML scores and implements per-IP scan tracking for graduated threat escalation.

_scan_counts: dict[str, int] = defaultdict(int)
_SCAN_BLOCK_THRESHOLD = 6  # Block after 6+ scans

def calculate(rule_score: float, ml_score: float) -> float:
    risk = 0.6 * rule_score + 0.4 * ml_score
    if rule_score >= 1.0:
        risk = max(risk, 0.90)  # Boost confirmed attacks
    return round(min(max(risk, 0.0), 1.0), 4)

def determine_action(risk_score, threat_type="normal", src_ip=""):
    # Honeypot interactions — already trapped, don't block
    if threat_type in {"honeypot_ssh", "honeypot_http"}:
        return "log"
    
    # Scan attacks — track count, escalate after threshold
    if threat_type in {"port_scan", "host_sweep", "stealth_scan"}:
        if src_ip:
            _scan_counts[src_ip] += 1
            if _scan_counts[src_ip] >= _SCAN_BLOCK_THRESHOLD:
                return "block"
        return "honeypot"
    
    # SSH brute force — always honeypot for deception
    if threat_type == "brute_force":
        return "honeypot"
    
    # Flood attacks — block immediately
    if threat_type in {"syn_flood", "icmp_flood", "arp_sweep"}:
        return "block"
    
    # Score-based fallback
    if risk_score >= 0.80: return "block"
    if risk_score >= 0.40: return "honeypot"
    if risk_score >= 0.25: return "rate_limit"
    if risk_score >= 0.15: return "log"
    return "allow"

4.5 Firewall and Honeypot Integration

4.5.1 nftables/iptables Manager (nft_manager.py)

The NFTManager class wraps Linux kernel firewall commands via subprocess calls. The system uses a hybrid firewall approach: nftables for forward-chain blocking (with the inet ntth_filter table) and iptables for NAT PREROUTING DNAT redirection (required for br_netfilter compatibility with bridged traffic).

Key design decisions in the firewall manager:

  • Bridge-scoped DNAT: All iptables DNAT rules use -i br-ntth to ensure redirection only applies to bridged VM traffic, preventing interference with upstream WiFi connectivity.
  • Targeted conntrack flush: Instead of flushing the entire connection tracking table (which disconnects all active connections), the system flushes only entries for the specific attacker IP using conntrack -D -s {attacker_ip}.
  • Gateway-safe blocking: nftables block rules use ip daddr != {gateway_ip} drop to ensure blocked attackers can still reach the gateway for DNS/DHCP, preventing cascading network disruptions.

4.5.2 Cowrie SSH Honeypot

Cowrie runs as a Docker container (image: cowrie/cowrie:latest) on port 30022 externally mapped to port 2222 internally. It simulates a Debian Linux shell environment, accepting any credentials and logging all attacker activity to a JSON log file shared via Docker volume. The backend's cowrie_watcher continuously tails this log file, parsing login events, command input, file downloads, and session closures in real-time.

4.5.3 Session Logger and Intelligence Escalation

The session_logger.py module tracks per-attacker command counts across honeypot sessions. When an attacker has executed 10 or more commands in the honeypot, the system escalates to an automatic block action. This two-phase approach maximizes intelligence gathering — capturing credentials, lateral movement attempts, and malware download URLs — before terminating the attacker's access.

4.6 Flutter Dashboard

The frontend is built with Flutter 3.19 targeting both Web and Android platforms from a single Dart codebase. The dashboard implements a persistent WebSocket connection to the backend, providing sub-second live updates for all security events. The UI follows a dark-themed "Command Center" design language optimized for security operations.

The dashboard consists of 9 screens:

  1. Login: JWT-based authentication with animated gradient background and system status badges
  2. Dashboard: Network Command Center with live incident counts, system health indicators, and real-time analysis feed showing the most recent threat events
  3. Devices: Protected Asset Inventory showing IP address, MAC address, hostname, vendor, risk score with color-coded severity, and administrative actions (Clear Risk, Trust/Untrust)
  4. Threat Map: Threat Intelligence Stream with severity filtering (High/Medium/Low), full-text search, and real-time sync indicators showing timestamp of last event
  5. Topology: Live Network Graph using force-directed layout, showing device relationships with color-coded legend (Gateway, Server, Trusted, Unknown, High-Risk, Honeypot nodes)
  6. Firewall: Containment Controls with Active/History toggle, showing rule type (block/redirect/rate-limit), target IP, creation time, expiry, and administrative delete capability
  7. Honeypot: Deception Surface with terminal-style command display showing captured attacker commands, attempted credentials, session duration, and attacker IP correlation
  8. System: System health monitoring showing sniffer status, event bus queue depth, database connections, and uptime
  9. Settings: Configuration management including dark/light theme toggle, notification preferences, and API endpoint configuration

4.6.1 WebSocket Live Updates

The dashboard maintains a persistent WebSocket connection to the backend at /ws/live. The connection uses automatic reconnection with exponential backoff (1s, 2s, 4s, up to 30s maximum). Events received via WebSocket trigger immediate UI updates through Dart's StreamController pattern, providing sub-second latency from threat detection to dashboard display.
